# 多国家出口目标与自动填补设计

## 背景

fanout 当前能够按地区批量创建 VPN Gate 出口，并通过每条隧道独立的 network namespace、OpenVPN 与 SOCKS5 端口提供不同出口 IP。现有健康检查会发现单条运行中隧道的出口 IP 异常并尝试换节点，但系统尚未持久化“某个节点模板在某个国家应始终保有多少个健康出口”的目标，也不能在一次操作中为多个国家分别设置数量。

本设计将一次性创建升级为声明式的国家出口保有机制：用户为“节点模板 + 国家”设置固定目标数量，系统尽力创建、持续检查，并在后续自动或手动协调中补足缺口。

## 目标

- 创建出口时支持同时选择多个国家，并为每个国家设置独立目标数量。
- 按当前实际可用数量尽可能创建，不因为候选不足而阻塞或在同一任务内持续等待。
- 持续保证每个目标组尽可能拥有指定数量的健康出口。
- 故障时只使用同国家节点替换，不允许跨国家替代。
- 优先在原槽位替换底层 VPN Gate 节点，保持 SOCKS5 端口、凭据、Xray 入站和客户端链接稳定。
- 自动协调之外提供“立即检测并自动填补”按钮。
- 目标数量下调时不自动删除健康出口，避免破坏已经分发的节点。

## 非目标

- 不持续预探测 VPN Gate 的全部节点。
- 不构建分布式、高可用或多机协调系统。
- 不自动迁移无法可靠识别模板归属的历史出口。
- 不在国家无可用候选时使用其他国家代替。

## 核心模型

每个保有目标以“节点后端 + 节点模板 + 国家”为唯一业务维度。同一个国家可以同时存在多组不同模板的目标。

目标记录包含：

```text
target_id
panel_kind
template_id
country_code
target_count
created_at
updated_at
last_reconcile_at
last_error
```

目标保存到 `/var/lib/fanout/country_targets.json`，采用临时文件写入后原子重命名。服务重启后继续维护。

由本功能创建的出口记录稳定的 `target_id`。出口更换 VPN Gate 节点后归属不变。历史出口没有可靠的模板元数据，继续作为未托管出口运行，不计入目标数量，也不被目标控制器自动创建或删除。

## 架构

### CountryTargetStore

负责目标记录的校验、持久化、查询和更新。目标数量必须是正整数。对已有“后端 + 模板 + 国家”再次提交时更新原目标，而不是创建重复目标。

### CountryReconciler

负责一次完整协调：统计状态、修复故障出口、计算缺口、挑选候选、验证候选并创建出口。自动定时、服务启动和手动按钮必须调用同一个入口。

协调器采用 single-flight 语义，同一时间只允许一个任务执行。后来的手动或定时请求复用当前任务状态，不得并行创建导致超量。

### HealthMonitor

保留现有健康检查职责，检查间隔调整为 60 秒。连续两轮失败后才确认故障，并立即请求协调器修复该出口。单次网络抖动不得触发换节点。

### ReconcileScheduler

- 服务启动并恢复状态后立即执行一次。
- 每 15 分钟执行一次完整协调。
- 手动按钮可以立即触发同一协调流程。
- 健康检查确认已有出口故障后立即触发该出口的修复，不等待下一个 15 分钟周期。

## 创建和协调流程

创建向导先选择节点模板，再多选国家并为每个国家填写固定目标数量。提交时先保存全部目标，然后启动一次异步协调任务。即使任务中途因进程重启而终止，启动后的协调仍会根据已保存目标继续处理。

单次完整协调按以下顺序执行：

1. 获取执行锁并刷新 VPN Gate 节点列表。
2. 读取全部目标及其托管出口。
3. 统计每组的健康、启动中、等待填补和超出目标数量。
4. 优先修复已有故障或等待填补的槽位。
5. 计算仍需新建的缺口。
6. 按国家选择未占用且不在冷却期的候选节点。
7. 建立 OpenVPN 隧道，并通过 SOCKS5 完整链路验证出口。
8. 成功后克隆对应模板、绑定出口并记录目标归属。
9. 候选耗尽后结束本轮，不在任务内部休眠和无限重试。

本轮实际创建数量为 `min(目标缺口, 实际验证成功的候选数量)`。目标缺口保留到下一次自动或手动协调。

## 候选选择与冷却

候选节点必须满足：

- 国家代码与目标一致。
- 未被其他出口占用。
- 符合当前“只用家宽”设置。
- 不在本轮失败集合中。
- 不处于失败冷却期。

候选优先按速度较高、会话数较少排序。连接或验证失败后进入 15 分钟冷却，本轮不得重复尝试；下一个正常自动协调周期到来时可以再次参与。

“剔除节点”表示将故障的 VPN Gate 后端从当前选择中排除并进入冷却，不删除用户已经分发的 Xray 入站。

## 健康判定

健康检查和新候选验收使用同一套完整链路：

```text
本地 SOCKS5 端口 -> 对应 netns -> OpenVPN -> 外部 IP 检测服务
```

健康必须同时满足：

- SOCKS5 用户名密码认证成功。
- TCP 请求成功。
- 返回合法公网 IPv4。
- 返回 IP 等于隧道建立时记录的 VPN 出口 IP。

主检测地址失败时使用备用地址，降低第三方服务异常造成的误判。已有出口连续两轮检查失败后才进入故障处理；新建候选必须在本次验证成功后才能计入健康数量。

## 故障修复

已有托管出口失效时，控制器保留原槽位、SOCKS5 端口、认证信息、Xray 入站和客户端凭据，仅更换同国家的 VPN Gate 后端。没有可用候选时将出口置为 `waiting_fill`，本轮结束，后续协调继续尝试恢复该槽位。

如果隧道建立成功但 SOCKS5 验证失败，应清理隧道资源并冷却候选。如果隧道验证成功但模板克隆或绑定失败，应回滚本次新出口，避免留下没有节点入口的孤立 SOCKS5。

VPN Gate 列表拉取失败、面板暂时不可用或 Xray 配置失败时，保留目标和已有健康出口，本轮报告错误并结束，后续协调重试。

目标记录同时保存 `panel_kind`。当前后端与目标后端不一致，或模板已经删除时，暂停该目标并展示明确错误，不得把不同后端中相同数值的模板 ID 错误关联。

## 目标变更与手动操作

目标数量增加后立即协调。目标数量降低后不自动停止多余的健康出口，而是显示“超出目标”。用户需要手动选择要停止的出口。

用户直接停止一个托管出口而目标数量不变时，系统会在后续协调中补齐。界面必须在停止操作前提示这一行为；如需永久减少，应先降低目标数量。

全局“立即检测并自动填补”按钮检查所有目标组，包括已有出口健康状态、故障替换和目标缺口。已有协调任务运行时，按钮显示当前进度，不启动重复任务。

## 界面

创建向导为每个国家显示最新节点列表中的空闲候选数。该数值仅供参考，因为候选仍需实际连接验证；目标数量可以大于当前候选数。

主界面增加“出口保有目标”区域，至少显示：模板、国家、健康数、启动中数、等待填补数、目标数、超出目标数、最近检测时间、下一次自动检测时间和最近错误。

异步执行进度复用现有 Job 展示机制，逐个国家报告成功、缺口和失败原因。

## 测试策略

单元测试覆盖目标持久化、缺口计算、候选排序、冷却、目标下调、single-flight 和状态恢复。协调器通过可替换的节点源、隧道创建器、健康探测器和 Panel 假实现进行测试，避免单元测试依赖真实 VPN Gate。

场景测试必须覆盖：

- 多国家分别设置不同目标数量。
- 候选不足时尽可能创建并保留缺口。
- 不跨国家替代。
- 故障后在原槽位用同国家节点替换。
- 无候选时进入等待填补，下一轮出现候选后恢复。
- 手动和定时触发不能重复创建。
- 目标下调不自动删除。
- 用户停止出口但目标不变时重新补齐。
- 模板删除、后端切换、节点列表失败和绑定失败。
- 服务重启后目标及托管出口归属恢复。
- SOCKS5 完整链路健康检查及备用检测地址切换。

## 验收标准

- 用户能在一次操作中为多个国家设置独立固定目标。
- 系统不会因某个国家无候选而阻塞其他国家。
- 每轮只创建实际验证成功的出口，候选耗尽后正常结束。
- 自动检查默认每 60 秒检查运行中出口，每 15 分钟协调缺口。
- 故障出口优先在原槽位更换同国家后端，客户端配置保持稳定。
- 国家暂时没有候选时保留缺口，后续自动或手动协调能够补齐。
- 并发触发不会超过目标数量。
- 目标下调不会自动删除健康出口。
